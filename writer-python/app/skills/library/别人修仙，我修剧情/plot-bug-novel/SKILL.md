# Plot Bug Novel

## Overview

Use this skill to help write an original Chinese webnovel built around: the protagonist enters a broken, unfinished爽文 world; everyone else cultivates power, but the protagonist finds contradictions in setting, timeline, identity, motivation, and rules, then forces reality to repair itself.

Default style: funny but not brainless,爽 but with logic, internet-flavored but not greasy, emotional beats visible through action and dialogue rather than plain explanation.

## Core Workflow

1. Identify the user's task type:
   - **设定/大纲** → read `references/core-setting.md`, `references/cool-points.md`, and `references/chapter-engine.md`.
   - **场景/世界大环境** → read `references/scene-environment.md`.
   - **正文试写/续写** → read `references/chapter-engine.md`, `references/emotion-expression.md`, `references/comedy-internet-voice.md`, and `references/character-voices.md`.
   - **爽点脑洞/反转设计** → read `references/cool-points.md` and `references/anti-cliche-checklist.md`.
   - **润色/改写** → read `references/emotion-expression.md`, `references/comedy-internet-voice.md`, and `references/anti-cliche-checklist.md`.
   - **让智能体长期写作** → read `references/templates.md` and apply the agent prompt templates.

2. Preserve the unique hook:
   - The protagonist does not win mainly by stronger fists.
   - The protagonist wins by catching contradiction, forcing truth, breaking forced剧情, or weaponizing logic.
   - The world itself is the broken system; the protagonist is the only person who sees the error report.

3. For every proposed chapter or scene, include these four layers unless the user asks for something shorter:
   - **设定漏洞**: what specific contradiction exists?
   - **场景压力**: why must it be exposed now?
   - **情绪推进**: what does the protagonist, opponent, and crowd feel beat by beat?
   - **爽点反转**: what changes after the bug is fixed?

4. Keep the prose original:
   - Do not copy characters, scenes, titles, dialogue, or distinctive setups from existing novels.
   - Use broad genre conventions only as raw material, then twist the mechanism.
   - Prefer fresh bug types over overused system rewards,退婚打脸,直播曝光,隐藏大佬, and全网震惊.

## Default Output Standards

When drafting prose:
- Write in Chinese.
- Use close third-person or light first-person depending on the user's preference; default to close third-person.
- Prioritize readable webnovel rhythm: short paragraphs, punchy dialogue, clean chapter hooks.
- Show emotion through silence,动作,表情,误会升级, crowd reactions, and delayed punchlines.
- Use internet words sparingly as seasoning: e.g. 破防, 离谱, 绷不住, 开盒, 版本管理, bug, patch, 回滚, 你人设没对齐.
- Avoid stuffing memes every paragraph.

When planning:
- Provide structured sections.
- Give concrete examples, not abstract advice.
- Add at least one “反常规处理” to prevent同质化.

## Must-Have Story Rules

- Every major爽点 must come from a concrete bug, not random luck.
- Every bug fix must have cost, side effect, or escalation.
- The protagonist can be witty, but should not become油腻装逼犯.
- Antagonists should not lose because they are stupid; they lose because the world record, timeline, or role logic betrays them.
- The system should be a校验器, not a神级技能发放机.
- Chapter endings should create a new question, not merely announce victory.
